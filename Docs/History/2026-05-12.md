## Проверка `word = word`

### Где создаются source words

В `engine/storage.py` внутри `_build_paragraph_payloads(...)`:

```python
for local_index, token in enumerate(tokenize_words(source_text)):
    global_index = paragraph_word_offset + local_index
    global_word_id = f"{paragraph_id}_w_{global_index}"
    words.append(
        {
            "id": global_word_id,
            "surface_text": token["text"],
            "normalized_text": token["normalized"],
            "order_index_in_paragraph": global_index,
            "order_index_in_segment": local_index,
            "segment_id": segment_id,
            "anchor_source_word_id": global_word_id,
            "is_function_word": 0,
        }
    )
```

Вывод:

- на уровне таблицы `source_words` сейчас:
  - один source token = одна строка
  - один source token = один `word_id`
  - `anchor_source_word_id` указывает сам на себя.

## Диагностика запуска backend engine

### Первичная ошибка

При запуске `run_lexo_engine_lan.bat`:

```text
[LEXO] Engine failed with exit code 103.
No Python at '"C:\Users\Ivan\AppData\Local\Programs\Python\Python311\python.exe'
```

### Причина

Файл:

- `.venv_backend/pyvenv.cfg`

указывал на старый Python:

```text
home = C:\Users\Ivan\AppData\Local\Programs\Python\Python311
executable = C:\Users\Ivan\AppData\Local\Programs\Python\Python311\python.exe
version = 3.11.9
```

На машине найден актуальный Python:

```text
C:\Users\ivank\AppData\Local\Programs\Python\Python312\python.exe
```

Вывод:

- `.venv_backend` была создана от удалённого/старого Python 3.11.
- Это была не ошибка LEXO-кода, а сломанная virtualenv.

### Неправильная первая попытка восстановления

Пользователь сначала выполнил команды из:

```text
C:\Users\ivank>
```

В результате была создана виртуалка:

```text
C:\Users\ivank\.venv_backend
```

Но LEXO использует:

```text
D:\Programs\LEXO\.venv_backend
```

Вывод:

- первая установленная virtualenv не использовалась LEXO.

### Правильное восстановление backend venv

Пользователь затем выполнил из:

```text
D:\Programs\LEXO>
```

Команды:

```bat
rmdir /s /q .venv_backend
C:\Users\ivank\AppData\Local\Programs\Python\Python312\python.exe -m venv .venv_backend
.venv_backend\Scripts\python.exe -m pip install --upgrade pip
.venv_backend\Scripts\pip.exe install fastapi uvicorn ctranslate2 transformers sentencepiece sacremoses numpy requests
```

Результат:

- `.venv_backend` создана правильно в проекте:
  - `D:\Programs\LEXO\.venv_backend`
- backend-пакеты установлены успешно.

Следующий шаг:

```bat
run_lexo_engine_lan.bat
```

## Диагностика запуска Windows UI

### Ошибка

При запуске Windows UI:

```text
[LEXO] Starting Flutter Windows UI...
[LEXO] API base URL: http://127.0.0.1:8765
The system cannot find the path specified.
[LEXO] Flutter app exited with an error.
```

### Причина

В `run_lexo_windows_ui_lan.bat` жёстко прописано:

```bat
set "FLUTTER_CMD=C:\src\flutter\bin\flutter.bat"
```

Путь не существует.

Пользователь проверил:

```bat
cd /d C:\src
```

Результат:

```text
The system cannot find the path specified.
```

Вывод:

- Flutter SDK удалён или больше не установлен в `C:\src\flutter`.
- backend engine уже восстановлен, но Windows UI launcher не может стартовать без Flutter.

### Что нужно сделать завтра

Если Flutter действительно удалён:

```bat
mkdir C:\src
cd /d C:\src
git clone https://github.com/flutter/flutter.git -b stable
C:\src\flutter\bin\flutter.bat doctor
```

Потом:

```bat
cd /d D:\Programs\LEXO
run_lexo_windows_ui_lan.bat
```

Если `git` не установлен:

- установить Git for Windows
- или скачать Flutter SDK zip вручную и распаковать так, чтобы существовал путь:

```text
C:\src\flutter\bin\flutter.bat
```
