## Сессия: Fail-closed финализация книги при unresolved QA-blocking сегментах

### Что сделано

- обновлён [engine/storage.py](/mnt/d/Programs/LEXO/engine/storage.py)
  - добавлены статусы книги:
    - `ready`
    - `qa_failed`
  - `_import_book_text(...)` теперь считает число `unresolved` сегментов после сборки `paragraph_payloads`
  - если unresolved blocking сегментов нет:
    - книга сохраняется как `ready`
    - книга становится active
  - если unresolved blocking сегменты есть:
    - книга сохраняется как `qa_failed`
    - в `error_message` пишется число unresolved QA-blocking сегментов
    - книга больше не активируется автоматически как готовая

- обновлён контракт `_select_segment_translation(...)`
  - финальный выбранный payload теперь получает `finalizable`
  - blocking semantic defects больше не считаются финализируемыми
  - если после retry/nbest/merge-cleanup чистый кандидат не найден:
    - сегмент остаётся диагностически сохранённым
    - но помечается как не финализируемый
    - `winner_reason` становится `no_clean_candidate_found`

- обновлён `_finalize_selected_payload(...)`
  - unresolved blocking кандидат теперь получает:
    - `quality_status = fail`
    - `decision_status = reject`
    - `alignment_confidence = 0.0`
    - `quality_score <= 45`

- обновлён [scripts/check_pipeline_regressions.py](/mnt/d/Programs/LEXO/scripts/check_pipeline_regressions.py)
  - добавлены проверки, что clean replacement path оставляет книгу в `ready`
  - добавлены проверки, что unresolved blocking сегменты переводят книгу в `qa_failed`
  - semantic blocking regression-ожидания синхронизированы с новым контрактом `reject + qa_failed`

### Почему это понадобилось

- раньше pipeline уже умел:
  - находить bad candidate
  - запускать retry / nbest / merge fallback
  - маркировать unresolved результат как `fail`
- но книга всё равно получала `ready`, а bad segment доходил до persisted final как `best available`

### Что изменилось по контракту

- теперь для blocking semantic defects контракт такой:
  - bad candidate не считается корректным финалом
  - если clean replacement не найден, книга не становится `ready`
  - unresolved сегмент остаётся диагностическим результатом, а не “тихим финалом”

### Что проверено

- `python3 -m py_compile engine/storage.py scripts/check_pipeline_regressions.py`
- `python3 scripts/check_pipeline_regressions.py`

### Итог

- bad segment больше не может тихо пройти в “готовую” книгу только потому, что он `best available`
- unresolved QA-blocking случаи теперь поднимаются на уровень статуса книги как `qa_failed`

## Сессия: Strict-equivalence whitelist для identical recipient forms в back-QA

### Что сделано

- добавлен [engine/qa_equivalence.py](/mnt/d/Programs/LEXO/engine/qa_equivalence.py)
  - введён узкий whitelist только для разрешённых identical-equivalent пар:
    - `everyone` = `everybody`
    - `someone` = `somebody`
    - `anyone` = `anybody`
    - `no one` = `nobody`
    - `no-one` = `nobody`
  - добавлены helper-ы:
    - `canonicalize_strict_equivalent(...)`
    - `are_strict_equivalent(...)`

- обновлён [engine/qa_verbs.py](/mnt/d/Programs/LEXO/engine/qa_verbs.py)
  - `verb_argument_drift` больше не срабатывает на identical recipient forms вроде:
    - `everyone` vs `everybody`

- обновлён [engine/qa_semantic_coverage.py](/mnt/d/Programs/LEXO/engine/qa_semantic_coverage.py)
  - strict-equivalence включён в token/back matching
  - `_find_back_tail_match(...)` учитывает whitelist-equivalence
  - добавлен inferred tail только для уже совпавшего `recipient/destination`, чтобы back-фраза без явного `to` не теряла роль при тождественном аргументе

- обновлён [scripts/check_pipeline_regressions.py](/mnt/d/Programs/LEXO/scripts/check_pipeline_regressions.py)
  - добавлен regression:
    - `recipient_everyone_everybody_equivalence_allowed`
  - обновлён regression на `Good morning to everyone`, чтобы он больше не считался unresolved из-за `everybody`

### Почему это понадобилось

- корректный сегмент:
  - `Nick says, "Good morning!" to everyone.`
  - `Ник говорит, доброе утро всем!`
  - back: `Nick says good morning, everybody!`
- раньше рубился ложно, потому что QA сравнивал:
  - `everyone`
  - `everybody`
  как разные строки, а не как тождественные формы

### Граница правки

- whitelist применяется только к identical recipient/person forms
- глагольные и смысловые near-paraphrase поблажки не добавлялись
- `make -> cook` и аналогичные кейсы остаются строгими и продолжают требовать retry

### Что проверено

- `python3 -m py_compile engine/qa_equivalence.py engine/qa_verbs.py engine/qa_semantic_coverage.py scripts/check_pipeline_regressions.py`
- `python3 scripts/check_pipeline_regressions.py`

    - `time_of_day`
  - удалены legacy block matcher-ы для article/copula/possessive/chapter/pronoun paths
  - `_resolve_unit_target(...)` больше не держит special-case ветки для удалённых block-unit типов

- обновлён [scripts/check_pipeline_regressions.py](/mnt/d/Programs/LEXO/scripts/check_pipeline_regressions.py)
  - старые regression-ожидания на `noun_phrase` / coordination-группы переведены на новый контракт:
    - такие группы больше не создаются
    - group-based split/backfill больше не должен происходить
  - сохранены проверки для живых специальных блоков:
    - `phrasal_verb`
    - `time_phrase`

### Почему это понадобилось

- часть ложных посадок слова в “чужое место” происходила не из strict runtime exact path, а из group/block backfill после него
- особенно это проявлялось на старых путях:
  - `noun_phrase`
  - coordination groups
  - degraded noun-group narrowing
- в результате блок мог считаться “в целом ok”, а отдельные слова внутри него садились не на своё место

### Что изменилось по контракту

- живыми блочными механизмами оставлены только:
  - `phrasal_verb`
  - `time_phrase`
  - `word_time`
  - `time_of_day`
- все прочие noun/article/coordination block-group path больше не должны создавать:
  - group coverage
  - split-to-units backfill
  - structural salvage

## Сессия: Временное отключение 2-го pass salvage-этапа

### Что сделано

- обновлён [engine/v2_core/coverage.py](/mnt/d/Programs/LEXO/engine/v2_core/coverage.py)
  - в `resolve_analysis(...)` отключены:
    - `_resolve_gap_zone_coverages(...)`
    - `_resolve_residual_segment_coverages(...)`
  - runtime coverage теперь останавливается после 1-го pass:
    - базовый lexical / parser / function-word слой
    - без gap-zone salvage
    - без residual добивки
  - в `resolve_analysis_debug_phases(...)` `pass2` временно приравнен к `pass1`, чтобы debug-вывод не создавал ложное ощущение второго активного этапа

### Зачем это понадобилось

- текущая задача сместилась с “получить больше покрытых слов” на “понять, как чисто работает 1-й этап”
- 2-й pass продолжал нарушать жёсткий контракт:
  - если нет подтверждённой посадки,
  - слово должно оставаться пустым,
  - а не получать догадочный target по соседству или по ordered salvage

### Что изменилось по контракту

- сейчас active word-only runtime работает так:
  - есть подтверждённая посадка на 1-м этапе -> слово получает target
  - нет подтверждённой посадки на 1-м этапе -> слово остаётся пустым
- 2-й salvage-pass временно полностью выключен из рабочего контура

### Что проверено

- `python3 -m py_compile engine/v2_core/coverage.py`
- `python3 scripts/check_pipeline_regressions.py`
