## Сессия: Анализ деградации `The Sunny Morning` на `nllb33` и фикс anti-repeat decode path

### Что выявлено

- книга `The Sunny Morning.txt` в базе `book_89842f038a1a` была импортирована через `facebook/nllb-200-3.3B`
- сегментация книги оказалась рабочей:
  - заголовки, chapter heading, предложения и реплики были выделены в отдельные segment-ы без потери порядка
- корневая деградация шла из translation layer:
  - `The Sunny Morning` -> повтор `Sunny Morning ...`
  - `Chapter 1: The New Day` -> `Глава 1: The New Day ...` с повтором title-хвоста
  - `"Good morning, Luna!" Tom says.` -> `"До". "До". ...`
  - `The cat says, "Meow."` -> шум/повтор `кококо ...`

### Что изменено

- обновлён [engine/translator.py](/mnt/d/Programs/LEXO/engine/translator.py)
  - `Nllb33Provider` отделён от общего decode path
  - для `nllb33` добавлены отдельные decode profiles:
    - base
    - retry
  - `nllb33` переведён на single-segment decode вместо общего batched path
  - добавлен dynamic `max_decoding_length` по длине segment-а
  - добавлен technical guard `_is_degraded_translation(...)` против loop/repetition output
  - при деградации для `nllb33` включается повторный более жёсткий decode pass

### Проверка

- `python3 -m py_compile engine/translator.py` -> OK
- helper smoke-check:
  - `The Sunny Morning` + looped output -> degraded = `True`
  - `Chapter 4: Home` + repeated `Home` output -> degraded = `True`
  - `The sun is bright.` + `Солнце ярко светит.` -> degraded = `False`
  - `It is a very good day.` + `Это очень хороший день.` -> degraded = `False`
- прямой runtime smoke-test `Nllb33Provider()` из WSL не выполнен:
  - в текущем Linux Python отсутствует пакет `ctranslate2`
  - живую модель нужно перепроверить из проектной среды / launcher-а, где доступен CT2 runtime

### Итог

- причина desktop-фриза `Load TXT` зафиксирована в истории и отложена как отдельный будущий фикс

## Сессия: Формализация MVP19 для quality gate перевода до alignment

### Что сделано

- по итогам диалога оформлено отдельное ТЗ в [MVP/MVP19_TRANSLATION_QUALITY_GATE_BEFORE_ALIGNMENT_PLAN.md](/mnt/d/Programs/LEXO/MVP/MVP19_TRANSLATION_QUALITY_GATE_BEFORE_ALIGNMENT_PLAN.md)
- зафиксирован новый целевой порядок pipeline:
  - сначала `EN -> RU`
  - затем quality-check для каждого segment-а
  - затем retry / n-best / fallback при плохом score
  - и только после этого `word alignment`

### Что входит в ТЗ

- проверка каждого segment-а, а не только подозрительных
- back-translation `EN -> RU -> EN` как semantic check
- quality flags:
  - `repetition`
  - `english_leftover`
  - `semantic_drift`
  - `bad_russian`
  - `tense_shift`
  - `suspicious_verb_choice`
  - `length_mismatch`
- поддержка нескольких кандидатов перевода на segment
- привязка alignment к качеству итогового `target_text`

### Итог

- сформирован отдельный MVP-план под новую архитектуру quality gate до alignment
- код не менялся, это только формализация ТЗ для следующего этапа

- исправление внесено в translation layer, а не в segmenter/storage
- цель фикса: остановить повтор/раздувание коротких `nllb33` segment-ов без возврата к book-specific hardcode

## Сессия: Анализ фриза desktop `Load TXT` при загрузке новой книги

### Что выявлено

- проблема найдена в desktop import path, а не в detail sheet / reader
- лог `DETAIL_SHEET_OPEN ...` не связан с `Load TXT` и не является причиной фриза

### Причина

- в [app/lib/src/api/api_client.dart](/mnt/d/Programs/LEXO/app/lib/src/api/api_client.dart) `POST /books/import-text` делает двойную полную JSON-сериализацию payload с текстом книги:
  - сначала для лога:
    - `developer.log('POST $uri payload=${jsonEncode(payload)}', ...)`
  - затем второй раз для реального запроса:
    - `request.write(jsonEncode(payload))`
- при `Load TXT` в payload уходит весь `source_text` книги
- это выполняется на UI isolate и может фризить desktop UI на больших `.txt`

### Усиливающие факторы

- в [app/lib/src/ui/desktop/screens/desktop_shell_screen.dart](/mnt/d/Programs/LEXO/app/lib/src/ui/desktop/screens/desktop_shell_screen.dart) файл целиком читается в строку на UI-потоке:
  - `final sourceText = await file.readAsString();`
- в [app/lib/src/api/api_client.dart](/mnt/d/Programs/LEXO/app/lib/src/api/api_client.dart) `_post()` и `_get()` используют практически бесконечный wait:
  - `Duration(days: 1)`
  - это не корень фриза, но ухудшает UX при проблемном импорте

### Итог

- наиболее вероятный корень desktop-фриза при `Load TXT`:
  - двойной `jsonEncode(payload)` для полной книги в `LexoApiClient._post(...)`
- изменение кода в этой сессии не выполнялось
- проблему нужно отдельно исправить позже
