# MVP23_9 — Anti-Regression Exact Code Fixes

## Цель

Зафиксировать не общую архитектуру resolver-а, а точные corrective-правки по коду, которые должны остановить текущую деградацию качества после `resolved v2`.

Главная задача:

- перестать строить ложные `compound`
- вернуть обычные `word`-links как основную форму alignment
- не давать ложным owner-решениям выталкивать живые content words в `rejected`

---

## 1. `engine/alignment_units.py`

### Что правим

- расширяем `GRAMMAR_WORDS`
- расширяем `GRAMMAR_POS`
- убираем широкий auto-compound
- оставляем только безопасные `SAFE_NOUN_NOUN_COMPOUNDS`
- убираем мусорный fallback `nounish`

### Точные изменения

- слова вроде `about`, `very`, `down`, `back`, `out`, `too`, `then` считаются grammar/function-like
- `ADV` перестаёт быть кандидатом в noun-like auto-compound
- generic `adj_noun` отключается
- generic `noun_noun` отключается
- compound строится только через whitelist
- неизвестное слово получает `unknown`, а не `nounish`

### Зачем

Именно здесь рождались ложные пары:

- `David likes`
- `talk about`
- `very friendly`
- `goes home`
- `him find`
- `music games`

---

## 2. `engine/alignment_features.py`

### Что правим

- ослабляем поддержку `compound` в scorer-е
- делаем `context_score` менее щедрым
- снижаем dictionary trust для compound

### Точные изменения

- `phrase_score`:
  - `phrase = 1.0`
  - `compound = 0.25`
- `dictionary_score`:
  - exact match для `compound` не получает phrase-level доверие
- `context_score`:
  - перестаёт почти автоматически давать высокий бонус любому короткому span

### Зачем

Иначе даже ложный compound получал:

- высокий `simalign`
- высокий `phrase`
- слишком мягкий `context`

и выигрывал у нормальных word-links.

---

## 3. `engine/alignment_resolver.py`

### Что правим

- убираем type-priority compound над word
- делаем winner selection более консервативным
- не даём compound выигрывать, если обычные слова внутри уже дают сопоставимое объяснение

### Точные изменения

- сортировка winners:
  - `phrase > word > compound`
- если внутренние single-word кандидаты по score почти не хуже compound, compound пропускается
- unresolved canonical words не должны улетать в `rejected` только потому, что ложный compound занял их source-range

### Зачем

Сейчас compound слишком легко становился главным winner и глушил нормальную локальную разметку.

---

## 4. Runtime / adapter layer

### Что делаем

- backend-ошибки в adapter не лечим
- adapter оставляем честным отображателем backend truth
- raw fallback работает только при отсутствии resolved

### Зачем

Иначе снова появятся две истины:

- одна в `segment_resolved_alignments`
- другая в runtime bridge

---

## 5. Обязательная операционная часть

После таких правок обязательно:

1. rebuild `segment_resolved_alignments`
2. проверить 3 книги:
   - `Introduction`
   - `The Bus Driver`
   - `The Sunny Morning`
3. проверить, исчезли ли:
   - `David likes`
   - `talk about`
   - `very friendly`
   - `goes home`
   - `him find`
4. проверить, вернулись ли:
   - `likes`
   - `talks`
   - `walks`
   - `smiles`
   - `old`

---

## 6. Критерий успеха

Правки считаются удачными, если после rebuild:

- ложные `compound` резко сокращаются
- `rejected` на content words заметно падает
- обычные lexical words снова получают нормальные links
- phrase/grammar кейсы не ломаются
- UI показывает ровно backend truth без дополнительного мусора
