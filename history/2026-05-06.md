## Сессия: Переключение `torch` на CUDA и проверка GPU-пути для `Qwen3-14B`

### Что сделано

- удалены CPU-only пакеты:
  - `torch 2.11.0`
  - `torchvision 0.26.0`
- установлены CUDA-сборки:
  - `torch 2.7.1+cu128`
  - `torchvision 0.22.1+cu128`

### Что подтверждено

- Windows-хост видит GPU:
  - `NVIDIA GeForce RTX 3060`
- в `.venv` теперь:
  - `torch.cuda.is_available() = True`
  - `torch.cuda.device_count() = 1`
  - `torch.version.cuda = 12.8`
  - `torch.backends.cuda.is_built() = True`
- `Qwen3-14B` теперь действительно стартует через GPU-путь

### Ограничения

- даже после включения CUDA `transformers` сообщает:
  - часть параметров остаётся на `cpu/disk`
- во время загрузки и запуска теста GPU была занята примерно на:
  - `9851 MiB / 12288 MiB`
- это подтверждает, что текущие `original` веса `Qwen3-14B` не помещаются целиком в `12 GB VRAM`
- из-за partial offload первый ответ остаётся медленным

### Вывод

- GPU-путь восстановлен
- текущий bottleneck — не отсутствие CUDA, а нехватка VRAM для полного размещения `Qwen3-14B` в текущем HF/original формате

## Сессия: Добавлен `BAT`-launcher для `Aya Expanse 8B GGUF` через `Ollama`

### Что сделано

- подтверждено наличие Windows `Ollama`:
  - `0.23.1`
- вручную подтверждено, что модель:
  - регистрируется в `Ollama`
  - быстро генерирует через `GGUF`
- добавлен launcher:
  - [scripts/run_aya_expanse_8b_ollama.bat](/mnt/d/Programs/LEXO/scripts/run_aya_expanse_8b_ollama.bat)

### Что умеет launcher

- проверяет наличие:
  - `Ollama`
  - `aya-expanse-8b-Q5_K_M.gguf`
- если модель ещё не зарегистрирована в `Ollama`:
  - автоматически пишет `Modelfile`
  - автоматически выполняет `ollama create`
- затем запускает:
  - интерактивный `ollama run aya-expanse-8b-q5`

### Почему потребовался отдельный `Modelfile`

- голый `FROM ...gguf` запускал модель как `completion`
- из-за этого она не отвечала как чат, а бесконечно продолжала текст
- в launcher зашит chat-template для `Aya Expanse`, чтобы интерактивный режим был ближе к нормальному assistant-поведению

### Дополнительный runtime-fix launcher

- первый вариант `BAT` падал сразу с:
  - `< was unexpected at this time.`
- причина была в batch-парсинге сырых `^<...^>` токенов внутри генерации `Modelfile`
- затем была найдена вторая проблема:
  - ложный `Failed to write Modelfile` из-за проверки старого `errorlevel` после `ollama show`
- launcher исправлен:
  - `Modelfile` теперь пишется безопасным `echo`-блоком
  - проверка идёт по факту существования файла
- повторный прогон подтвердил:
  - мгновенное падение устранено
  - launcher доходит до `ollama create`
- затем выявлен ещё один runtime-дефект:
  - `Ollama` отклонял первый chat-template с `.Messages` и `eq .Role "user"`:
    - `template error: bad character U+0022`
- template упрощён до безопасного prompt-only варианта:
  - `System + Prompt + Chatbot token`
- это снижает риск parser-ошибки в `Modelfile` и оставляет интерактивный chat-path рабочим для локального запуска
- после этого был найден ещё один чисто batch-дефект:
  - `ollama create` завершался с `success`, но launcher всё равно падал на
    - `Ollama create failed with code .`
- причина:
  - `%ERRORLEVEL%` читался внутри `if (...)`-блока без delayed expansion
- launcher исправлен:
  - включён `EnableDelayedExpansion`
  - код возврата после `ollama create` теперь читается как `!ERRORLEVEL!`
- далее был найден корневой дефект prompt-контракта:
  - в `Modelfile` реально записывались экранированные токены вида `^<...^>`, а не настоящие `Aya` special tokens
- из-за этого модель:
  - печатала служебные токены в ответ
  - продолжала текст как `completion`
  - игнорировала короткий форматный prompt
- решение:
  - генерация `Modelfile` вынесена в отдельный helper-скрипт:
    - [scripts/write_aya_ollama_modelfile.ps1](/mnt/d/Programs/LEXO/scripts/write_aya_ollama_modelfile.ps1)
  - `BAT` больше не строит template через `cmd`-escaping
  - launcher теперь каждый запуск пересобирает модель в `Ollama` из актуального `Modelfile`
- повторный прогон подтвердил:
  - `Modelfile` пишется с реальными токенами `Aya`
  - `ollama create` завершается `success`
  - launcher доходит до `Starting interactive chat`

### Валидация для `A1-A2`

- число строк должно совпадать с числом EN токенов

  - `—`
