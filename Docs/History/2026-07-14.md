## Незавершённая задача: удалить hardcoded-слова из production-кода

Пользователь установил категорический запрет на английские слова, фразы, переводы и книжные исключения, вписанные непосредственно в рабочий код. Словарная логика должна получать данные только из проверенных book layer/seed/global JSON и структурных признаков, а не из скрытых таблиц Python/Dart.

### Найденные нарушения

- `Studio/Backend/engine/storage.py`: встроенные RU/UK словари для конкретных `book_id`, hardcoded phrase fallback и исключения словоформ `walks into`/`looks at`/`sits down`.
- `Virgil/App/lib/src/workbench/virgil_workbench_builder.dart`: повторные исключения для трёх конкретных фраз.
- `Studio/Backend/engine/virgil_core_dictionary.py`: словесная таблица `TITLE_PROPN_ALIASES`.
- `Studio/Backend/engine/segment_translation_qa.py`: списки конкретных английских, русских и украинских слов, влияющие на QA.
- `Studio/Backend/engine/structural_translation_rerank.py`: лексический список отрицаний.
- `Studio/Backend/engine/tts/tts_text_normalizer.py`: списки артиклей, местоимений, форм `be`, прилагательных, существительных, чисел и фиксированных фраз.
- `Studio/Backend/engine/tts/tts_segmenter.py`: списки конкретных слабых начал/окончаний и английских заголовков.

### Согласованный план

1. Удалить книжные словари и проверки конкретных `book_id` из production-кода.
2. Удалить hardcoded phrase fallback; при отсутствии проверенного seed/book layer работать fail-closed.
3. Сопоставлять варианты фраз через `source_forms`/`occurrences` из данных, без словесных исключений.
4. Удалить словесные POS-алиасы; исправлять POS структурно или подтверждёнными данными слоя.
5. Перевести translation QA на POS/dependency-признаки.
6. Убрать лексические TTS-эвристики; использовать пунктуацию, длину, структуру сегментов и внешние языковые данные.
7. Добавить защитный тест, запрещающий возврат встроенных книжных словарей и EN→RU/UK таблиц в production-код.
8. Пересобрать словари/пакеты, проверить повторную сборку `changed=false`, backend tests и Flutter tests.
9. Разделить чрезмерно большой `storage.py`, вынеся словарный контур в отдельные модули.
