  - для проблемного `provider_fallback` сегмента retry теперь сначала запрашивает до `5` кандидатов у той же модели
  - каждый кандидат отдельно прогоняется через текущий QA
  - победитель выбирается через существующий ranking по quality/depth flags
  - старый цикл из `3` одинаковых single-best попыток оставлен как fallback, если provider не умеет `n-best`

- обновлён [scripts/check_pipeline_regressions.py](/mnt/d/Programs/LEXO/scripts/check_pipeline_regressions.py)
  - добавлен synthetic regression, где single-model `top-5` выбирает лучший кандидат вместо base translation

### Итог

- QA больше не ограничен повтором одного и того же single-best ответа там, где модель умеет вернуть несколько гипотез
- для проблемных сегментов pipeline теперь может выбрать лучший вариант из `top-5`, не меняя основной runtime-маршрут книги

## Сессия: Детальный разбор word/block alignment на `The Sunny Morning`

### Что проверено

- книга `The Sunny Morning` была отдельно просмотрена не на уровне segment QA, а на уровне:
  - tap по английскому слову
  - tap по английскому блоку
  - `detail_sheet`
  - фактического `word -> target span` выравнивания

- подтверждены реальные alignment-проблемы, которые не являются translation-quality bug:
  - `Goodnight` попадает только в `Спокойной`, а не в полный span `Спокойной ночи`
  - `are` в `How are you?` остаётся без нормального владельца target-span
  - `you` в `thank you` может уезжать в соседний reporting clause
  - `7:00 AM` разбивается по токенам неровно и даёт слабый time block

### Что показал анализ кода

- основной источник проблемы локализован в [engine/word_alignment.py](/mnt/d/Programs/LEXO/engine/word_alignment.py), а не в UI
- `detail_sheet` в [engine/storage.py](/mnt/d/Programs/LEXO/engine/storage.py) в целом честно показывает уже собранный alignment и не является первичным источником drift

- найдены главные слабые точки текущего aligner:
  - `_match_fixed_phrase_unit(...)` сейчас пустой и не закрепляет устойчивые phrase blocks
  - `_apply_special_phrase_overrides(...)` фактически покрывает только `pronoun + be + adjective`
  - `_aggregate_target(...)` строит слишком широкий `min(start)..max(end)` span и из-за этого иногда тянет лишний target-хвост или оставляет часть перевода вне блока
  - для grammar/function words и коротких phrase-patterns нет жёсткого anti-orphan контроля

### Договорённость на продолжение

- alignment engine не переписывать и не ломать
- дорабатывать текущий `word_alignment.py` точечно
- фокус следующего шага:
  - fixed phrase units
  - phrase overrides
  - контроль orphan source words
  - стабилизация one-to-many span-кейсов без общего рефактора пайплайна
