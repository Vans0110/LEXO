## Сессия: Доводка lifecycle для `resolved alignment`

### Что сделано

- в backend API добавлен новый маршрут:
  - `/books/rebuild-resolved-alignment`
- `rebuild_book_simalign(...)` теперь сразу пересчитывает:
  - `segment_resolved_alignments`
- после полной пересборки книги через:
  - `rebuild_book_quality(...)`
  - `_import_book_text(...)`
  также автоматически вызывается:
  - `rebuild_book_resolved_alignment(...)`

### Техническая зачистка

- при очистке runtime-контента книги теперь удаляются связанные записи:
  - `segment_resolved_alignments`
- при удалении книги также удаляются её записи из:
  - `segment_resolved_alignments`

### Зачем

- runtime уже читает `resolved alignment` как основной слой
- до этой правки `resolved` мог отставать от свежего `SimAlign` и от полной пересборки книги
- теперь lifecycle стал консистентнее:
  - import / rebuild quality / rebuild simalign
  - затем актуальный `resolved alignment`

### Проверка

- `python3 -m py_compile engine/api.py engine/storage.py`
  - без ошибок
